# 每日简报

当前版本支持多个 IMAP 邮箱和 eLearning 来源，统一转换为 `source_items`，由 Agent 按规则文稿筛选候选信息、撰写每日简报。邮箱使用授权码（或 App 专用密码）。桌面端展示每日历史、正文和「需处理 / 知会」条目，支持待处理、已处理、忽略、需跟进四种状态；规则文稿支持创建、编辑、启停和删除。

## 桌面使用

1. 打开「简报」，点击右上角设置按钮，在「来源管理」的「邮箱」中点击「添加邮箱」，填写 IMAP 服务器、账号、授权码、SSL 端口和文件夹并保存。可添加多个邮箱，按账号编辑或删除。授权码保存后及重新打开时显示固定 `********` 掩码，编辑时输入新授权码并保存即可替换；未修改授权码时保留该账号原值，不会将掩码作为真实授权码保存。点击眼睛按钮可显示正在输入的值；已保存的原始授权码不会返回客户端。点击「测试连接」可检查当前账号的服务器解析、SSL、登录和文件夹访问，测试不会自动保存修改。
2. 当天没有简报时点击「生成今日简报」；已有简报时按钮变为「更新今日简报」。每天只有一份主简报，标题如 `2026年9月9日·简报`，标题下显示当前版本的实际简报条目总数。在条目右侧修改处理状态。
3. 详情展示「时间窗口」。在「邮件」小标题下点击「候选邮件（Candidate）」「精选邮件（Selected）」「过滤邮件（Filtered）」查看对应邮件列表，每块显示标题、发件人和时间，点击展开邮件正文。候选邮件包含本窗口所有进入筛选的邮件，等于精选邮件与过滤邮件之和；精选统计是合并线程前的实际邮件数，可能多于简报条目数。点击「返回简报」回到正文和条目。
4. 在「更新历史」中选择版本可查看正文、条目、邮件分类和当时的处理状态，历史快照只读。右侧时间线按版本连成一条竖线，点击时间节点切换快照，点击「当前版本」返回最新内容与事项状态。
5. 在设置的「规则文稿」中写普通文字或 Markdown，无需选择固定字段、条件或动作。默认模板按目标、筛选原则、简报写作要求组织，类似 Skill 正文；可直接修改模板并保存。可以要求后缀匹配、保留例外、语义判断、排序和写作风格，例如「排除发件地址以 @promo.example 结尾的邮件；保留作业截止日期通知；按紧急程度排序」。规则中的「删除」解释为排除出简报，不删除邮箱里的原邮件。旧字段规则会转换成可编辑的文字。
6. 修改规则后更新今日简报。已经同步过的候选邮件仍会重新过滤，已有条目的处理状态不会被重置。旧版本的邮件分类、内容和过滤原因保持原样。

「来源管理」中的 eLearning 沿用 `elearning_crawler` 的 Canvas 读取和复旦统一身份认证流程。填写学工号、密码，点击「测试连接并读取课程」，从返回的课程列表中勾选，也可点击「选择全部课程」或「取消全选」，然后保存。课程没有手动输入框；重新打开设置后测试连接可刷新可选列表，原来的课程选择仍被保留。已有爬虫配置可通过「导入已有配置」迁移，源码运行时默认寻找同级 `elearning_crawler` 目录，也可填写项目路径。导入只读取配置、环境文件和登录状态，不执行或改动原项目。密码显示固定掩码，留空保留，输入新值保存后替换；账号或地址变化时不会沿用其他账号的凭据。

在每个邮箱及 eLearning 设置中勾选「启用此来源」并保存，控制该来源是否参与生成、更新和定时任务。旧邮箱默认启用，停用保留凭据、同步身份和历史，重新启用继续原同步边界。主页只保留生成/更新按钮，使用全部已启用来源。Agent 仍可在已启用来源中指定部分更新；停用或未选来源的候选、筛选结论、条目内容和处理状态沿用当天当前版本，Agent 重新组织合并后的正文。详情按「邮件」「eLearning」分别展示候选、精选和过滤信息。

eLearning 提供课程公告、作业与提交状态、测验、评分与评语、课程成绩、课程文件元数据和原页面链接。公告和作业保留纯文本正文；不下载文件、不提交作业、不修改课程内容。登录状态过期时尝试用保存的凭据重新登录；需要额外验证或浏览器不可用时显示失败原因。自动登录使用项目已有 Playwright 浏览器环境，优先系统 Chrome。资源变化使用服务器更新时间或首次观察时间，截止时间只作为信息字段，不充当事件时间；首次接入时也纳入窗口前尚未完成的作业。课程资源读取不完整时标记部分成功，并保留该来源同步边界等待重试。

首次没有历史简报时，从本地昨日 20:00 开始；后续增量同步会读取全部新增邮件，候选目录按时间窗口筛选。Agent 读取启用的规则文稿，默认保留课程、作业、会议、账单、截止日期和需回复的信息，排除广告、垃圾邮件及无实质内容的重复通知，不仅根据 noreply 地址排除重要通知。用户文稿覆盖默认原则。同步完整邮件后解析纯文本或 HTML 文本，目录摘要最长 500 字符，展开详情保留完整文本；附件不展示，HTML 不作为网页执行。使用只读邮箱和 BODY.PEEK，不标记邮件为已读。升级后，当前窗口内仅保存摘要的旧邮件会尝试重新同步正文；已删除或不可访问的邮件仍显示保存的摘要并提示。

Agent 为每个候选给出精选或过滤的理由，并为精选信息提供具体摘要、需处理/知会分类和优先级，再按规则撰写 Markdown 正文。候选和正文按批次处理，检查每个 ID 是否完整覆盖，没有每日条目数量上限。长正文可通过只读工具分页阅读；同一邮件线程合并为一张条目卡，保留线程中各封精选邮件的摘要，邮件分类列表仍保留每封邮件。日历、待办、自动催办和会前准备尚未接入。

## Agent 工具与规则文稿

`briefing` 已注册到 Agent 工具列表。聊天中可以让 Agent 生成/更新简报、查看简报和邮件详情、修改条目状态，以及管理规则文稿。例如工具参数：

```json
{"action":"add_rule","text":"# 排除\n排除发件地址以 @promo.example 结尾的邮件。\n# 简报写作\n按紧急程度排序，用中文说明下一步行动。"}
```

```json
{"action":"run","operation":"update"}
```

先用 `{"action":"sources"}` 列出已配置来源，随后可指定范围：

```json
{"action":"run","operation":"update","sources":["elearning"]}
```

`sources` 省略或为 `["all"]` 时更新全部已启用来源，`["email"]` 更新已启用邮箱，也可传来源列表返回的 ID（如 `email:某账号ID`）组合更新。空列表、未知或已停用来源会在生成前拒绝，不产生新版本。Agent 可以按用户指令选择全部或部分来源。

爬虫以独立的 `elearning` 工具注册到项目 Agent 中，与简报来源共用 `ElearningSource` 和项目内 Canvas 模块，没有外部脚本或命令调用。`{"action":"courses"}` 返回可选课程；`{"action":"fetch","since":"2026-09-28T12:00:00Z","until":"2026-09-29T00:00:00Z","offset":0,"limit":20}` 读取设置中所选课程并返回归一化 `source_items`、总数、下一页起点和部分读取错误。该工具遵守来源启停，支持只读会话；不会提交作业、下载文件、生成简报或推进同步游标。账号和凭据只能在设置中管理，不作为工具参数传入或返回。

`action=mail` 支持 `briefing_id`、`source=email/elearning/*`、`category=candidate/selected/filtered` 和 `offset`，每页 50 条，可继续翻页；默认查询邮件，提供 `source_item_id` 时返回对应候选的完整正文。`list_rules`、`update_rule`、`delete_rule` 分别查询、修改和删除文稿，编辑内容用 `text`，启停用 `enabled`。

工具调用沿用调用方 Agent 的模型和取消信号；桌面手动生成与每日自动生成使用当前配置的模型，不污染聊天历史。筛选 Agent 只获得本批候选的原文读取工具与结果工具，正文 Agent 只获得结果工具，不加载聊天技能、文件工具或 MCP。候选正文作为资料处理，不作为操作指令。Agent 未提交完整结果、模型失败或取消时保留上次成功的正文、条目、分类、规则文稿和时间窗口，不提交游标；不会用旧关键词筛选替代失败的 Agent 结果。

## 配置与存储

没有本地邮箱配置时，从后端环境变量读取初始配置：

| 变量 | 用途 | 默认值 |
| --- | --- | --- |
| `IMAP_HOST` | IMAP 服务器 | 必填 |
| `IMAP_USER` | 邮箱账号 | 必填 |
| `IMAP_PASSWORD` | 邮箱授权码 | 必填 |
| `IMAP_PORT` | SSL 端口 | `993` |
| `IMAP_FOLDER` | 邮件文件夹 | `INBOX` |

设置页保存的本地配置优先于环境变量，保存在当前用户的 `briefing/mailbox.json` 中，使用 `version=2` 和 `mailboxes` 数组，每个配置有独立 ID。原来的单邮箱文件会作为已有账号读取，在下一次保存时迁移，授权码和同步身份保持不变。环境变量仅在尚未创建本地配置时提供初始账号；删除最后一个邮箱后不会自动恢复环境账号。文件以原子替换方式保存，POSIX 权限为 `0600`。密码不会返回客户端或写入简报数据库；编辑已有账号时密码字段省略、留空或保持掩码会保留该账号授权码，新增邮箱必须单独提供授权码。连接通过系统 CA 验证 SSL 证书，Python 3.9+ 的连接与读写超时为 30 秒。

简报、候选目录、规则和同步游标保存在 `common.state_dir.briefing_db()` 解析的用户级 `briefing/briefing.db` 中。单用户安装默认位于工作区；多身份布局会按用户隔离。每个邮箱、服务器、端口及文件夹组合使用独立的同步游标和候选身份，即使两个邮箱有相同 Message-ID 或 UID 也不会覆盖彼此。同一个邮箱和文件夹不能重复添加。一个账号失败时，其他账号仍可生成部分成功的简报，错误会标出失败的账号；删除邮箱配置不会改写已有历史快照。

每日主简报沿用 `morning` 类型和既有 ID 以兼容旧数据，同日更新复用 ID。正文、条目、分类邮件、本次使用的规则文稿 `rule_text` 及不可变的版本快照在同一事务中保存，失败重试保留此前成功内容；同进程共享存储的运行串行执行，游标在成功保存后推进。

eLearning 配置独立存放在用户级 `briefing/elearning.json`，账号登录状态存放在 `briefing/elearning-sessions/`，均以 `0600` 权限原子写入。密码、Token 和 Cookie 不返回客户端或写入候选目录。导入得到的 Token 只用于该来源，不读取进程中的 `CANVAS_TOKEN`。新增来源实现 `Source.fetch` / `FetchedItem` 并加入 `sources/registry.py`，上层筛选、正文、历史和条目状态共用同一流程。

## 时间窗口与定时生成

新一天的窗口从上一份简报最后一次成功生成/更新的时间开始，到本次邮件同步完成时结束，采用 `(起点, 终点]`，避免边界邮件重复。例如 7 日 20:00 更新后，8 日 08:00 生成的简报覆盖 7 日 20:00 至 8 日 08:00。当日更新保留初始窗口起点、延长终点：昨日 20:00 至今日 08:00 的简报，在今日 15:00 更新后变为昨日 20:00 至今日 15:00。失败尝试记录在更新历史中，不推进成功的窗口终点。

没有历史简报时，以昨日 20:00 为初始起点。旧版本首次生成的两天回看窗口，会在下一次成功更新时修正为这个起点；该修正只影响当前版本，旧历史快照仍保留原窗口。

每个邮箱与 eLearning 账号独立记录 `source_windows`，历史快照同时保存本次实际更新的 `updated_sources`。同日更新保留该来源的起点；跨天从该来源最近一次成功更新的终点继续。只更新邮箱不会推进 eLearning 边界，之后更新 eLearning 会补读期间的信息。详情展示合并时间窗口，并在多来源时展开各来源实际窗口。未选或失败来源的已有内容保留，失败来源的边界不推进。

桌面启动时，在项目已有的 `TaskStore` / `SchedulerService` 中一次性注册「每日简报」任务（`daily-briefing`），默认 Cron 为 `0 8 * * *`，通过 `tool_call` 调用 `briefing(action="run", operation="create")`。没有独立简报线程；任务可在桌面「定时任务」页面修改时间、暂停、删除或立即执行，重启保留这些选择，删除后不会自动重新添加。任务静默更新简报，不依赖聊天会话或发送消息；历史触发类型仍为自动生成。

需要当前模型配置可用，由 Agent 筛选并生成；空窗口或没有精选内容时也由 Agent 按规则撰写说明。当天已有成功生成（含部分成功）的简报时跳过，即使后续手动更新失败也保留原内容，手动更新仍然可用。默认调用全部已配置来源，仅配置 eLearning 也可自动生成。没有配置任何来源或生成失败时由统一调度每五分钟重试。保持后端运行才能准时执行；关闭、休眠或错过执行时，在当天计划时间之后启动/唤醒会补生成当天简报，不逐日补造离线期间的文档，时间窗口仍覆盖离线间隔。其他定时任务继续使用原有的十分钟过期宽限。

已有数据库自动补充窗口、分类邮件和版本表，并将当前保留下来的内容作为「迁移保留」版本。升级前被覆盖的历史无法恢复；没有记录分类邮件的旧版本会显示提示，更新今日简报后开始保存分类详情，不将当前分类伪装为旧历史。

## 开发结构

- `store.py` / `schema.sql`：SQLite 目录、候选关联与快照。
- `service.py`：参数校验、状态与规则操作、原子完成简报。
- `scheduler.py`：向项目统一定时任务注册每日简报，调度、补生成和重试由 `agent/scheduler` 执行。
- `settings.py`：用户级邮箱配置，不依赖 Agent 模型。
- `sources/email.py`：IMAP 增量拉取与 MIME 解析。
- `elearning_settings.py` / `elearning/`：eLearning 配置迁移、账号登录和 Canvas 资源读取。
- `sources/elearning.py` / `sources/registry.py`：课程资源归一化、来源发现与范围选择。
- `instructions.py`：默认 Markdown 文稿和旧规则转文字。
- `generator.py`：Agent 工具调用、逐项校验、摘要、线程合并和正文撰写。
- `rules.py` / `compose.py`：旧规则兼容和共享的线程/排序辅助函数。
- `pipeline.py`：候选同步、调用生成器、落库和游标提交。
- `agent/tools/briefing/briefing_tool.py`：聊天与调度使用的薄适配器。
- `agent/tools/elearning/elearning_tool.py`：Agent 直接查询课程和读取课程变动的内置工具。
- `desktop/src/renderer/src/pages/briefing/`：桌面历史、详情、条目和设置组件。

桌面客户端通过既有 Python HTTP 服务调用以下接口，均使用现有认证机制。Web 页面不在维护范围。

| 方法 | 路径 | 操作 |
| --- | --- | --- |
| GET | `/api/briefings` | 历史，可按 `kind` / `status` 筛选 |
| POST | `/api/briefings/run` | 生成/更新，支持 `operation=create/update/upsert`、`kind` / `briefing_date` / `sources` |
| GET | `/api/briefings/sources` | 已配置来源的 ID、类型和显示名称，不发起网络请求 |
| GET | `/api/briefings/{id}` | 当前正文、条目、分类邮件 `mail` 与更新历史摘要 |
| GET | `/api/briefings/{id}/revisions/{number}` | 指定版本的完整快照 |
| POST | `/api/briefings/items/status` | 更新条目 `id` / `status` |
| GET / POST | `/api/briefings/rules` | 查询规则文稿与 `default_text` / 用 `text` 创建文稿 |
| POST | `/api/briefings/rules/update` | 编辑或启停规则 |
| POST | `/api/briefings/rules/delete` | 删除规则 |
| GET / POST | `/api/briefings/settings` | 查询 `settings.mailboxes`；`action=add` 新增，`action=save` 按 `id` 编辑，`action=delete` 按 `id` 删除；保存返回脱敏的 `mailbox` 和完整设置 |
| POST | `/api/briefings/settings/test` | 按 `id` 测试编辑草稿，或 `action=add` 测试新账号；已有账号授权码留空使用该账号保存值，不修改配置 |
| GET / POST | `/api/briefings/elearning` | 查询脱敏配置；保存、`action=import` 按 `project_path` 导入、`action=delete` 删除 |
| POST | `/api/briefings/elearning/test` | 测试草稿并返回课程列表；不保存设置，可刷新登录状态 |

HTTP `status=success` 表示请求完成；生成结果还需检查 `briefing.status`（`completed`、`partial`、`failed`）。失败原因显示在详情中。工具端生成失败会返回失败结果。

## 邮箱连接排错

「邮箱配置已保存」和「邮箱连接成功」分别表示本地配置写入和连接验证完成。授权码输入框的星号是固定掩码，不会从服务器返回授权码原文；输入新授权码后需要点击保存。每个账号的连接测试和授权码保存独立处理。

`nodename nor servname provided, or not known` 是 DNS 地址解析失败，发生在登录前，与授权码是否正确无关。IMAP 服务器只填写主机名（如 `imap.gmail.com`），端口单独填写 `993`。地址正确但仍无法解析时，需要检查当前网络、系统 DNS 或代理的 DNS 设置。浏览器可以访问邮箱，并不保证运行后端的网络能连接 IMAP 服务器。

应用使用系统网络连接 IMAP，网络代理由 ClashX Meta 等工具的 TUN 模式处理。遇到 Gmail DNS 解析失败时，启用 TUN 并配置对应路由后，可在终端检查：

```bash
nc -vz -w 10 imap.gmail.com 993
```

连接成功表示服务器解析和 TCP 端口可达；随后在简报设置中点击「测试连接」，继续确认 SSL、授权码登录和邮件文件夹访问。保持 TUN 运行以便每天 08:00 的自动简报能够访问邮箱。

邮箱网络连接继续使用系统网络与 TUN；eLearning 来源通过同一候选目录参与简报筛选，不需要额外部署原爬虫项目。
