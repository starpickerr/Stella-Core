## 主动发送背景与定义

Stella 当前可从部分外部渠道接收消息并回复，但缺少由 Stella 自行发起消息的统一能力。用户希望 Stella 在没有近期入站消息的情况下，也能主动向指定目标发送通知或结果，例如定时任务完成后的消息。新增能力应覆盖本轮允许的每一个发送渠道，不能只提供渠道选项而没有真实发送路径。

“主动发送”指由 Stella 的事件、任务或用户操作触发出站消息，不依赖收件人刚刚向 Stella 发消息，也不依赖短时有效的回复上下文令牌。它不表示可以绕过平台的接收条件、机器人权限、频率限制或管理员撤销凭证的结果。

## 1. 发送渠道范围

主动发送的渠道选择器**最多只可能出现以下三个选项，且只显示当前已连接的渠道**：

1. **客户端**：由 Stella 向用户已登录的**电脑客户端**发送操作系统通知，呈现为系统通知横幅或通知中心条目，形式参照用户提供的截图：Stella 图标、通知标题和简短正文，由系统展示时间。它不是新建对话、聊天消息或仅在 App 内显示的提示。本轮不包含手机通知。
2. **Telegram Bot**：通过已配置的 Telegram 机器人发送至符合平台接收条件的聊天。
3. **企业微信智能机器人**：通过企业微信智能机器人的 WebSocket 长连接主动发送至指定会话。

这三个选项都必须能够实际发出消息，并向触发方报告结果。不得在本轮主动发送选择器中加入个人微信、QQ、飞书、钉钉、Slack、Discord、普通企业微信应用或其他渠道；这些渠道已有的入站或被动回复能力不因此删除。本轮的“企业微信智能机器人”特指支持主动推送的长连接模式，不把其他企业微信接入方式自动视为等价。

### 发送前必须建立渠道连接

- 三个渠道都必须先在 Stella 中完成连接或绑定，且目标具备接收条件，才能作为可发送目标。渠道选择列表只包含已连接的渠道；未连接的渠道不显示为选项，也不能保存或发送。若当前一个渠道都未连接，在列表外提示先连接渠道。保存后若连接断开，保留原设置并标记需要重新连接，实际发送前须重新检查并报告失败，不自动改选其他渠道。
- **客户端**：用户的 Stella 电脑客户端已连接到当前 Stella 实例，且系统允许 Stella 显示通知。不要求打开某段对话。
- **Telegram Bot**：机器人已配置并可用；目标用户已先与机器人建立聊天，或目标群已加入机器人，Stella 已取得该目标的有效聊天标识。
- **企业微信智能机器人**：机器人已配置并完成 WebSocket 长连接认证；目标用户或会话已与该机器人建立可发送关系，且机器人具有发送权限。
- “已经建立连接”是接入和接收资格要求，不等于要求收件人在发送前几分钟内再次发消息。

## 2. 发送行为

- 由 Stella 主动发起消息时，用户或任务可以在上述三个渠道中选择目标渠道与接收对象；发送操作应使用明确保存或传入的目标，不能把最近一次来信者默认为收件人。选择“客户端”时，通知发送到该用户已登录且允许通知的 Stella 电脑客户端；不要求选择手机或其他设备。
- 三个渠道均应在没有近期入站消息的情况下完成发送。Telegram 私聊须由用户先与机器人建立会话；企业微信智能机器人须已完成长连接认证并具备目标会话的发送权限；客户端提醒不要求用户正在打开 Stella 或某段对话。
- 发送成功必须以外部渠道或客户端通知服务确认接收为准，不能仅以 Agent 生成了文本、请求已排队或调用未抛异常作为成功。客户端提醒应具备可检查的投递结果；设备禁用通知时应如实反映受限状态。
- 目标不可达、平台拒绝、权限不足、连接中断或凭证失效时，向触发方返回可见失败原因；不得静默成功，也不得未经用户选择自动改投其他渠道。
- 凭证或连接可以按平台支持的方式续期、重连；但发送流程不得要求收件人为了刷新回复窗口而先发一条消息。凭证被管理员撤销等情况仍应正常报错。
- 发送能力应遵守 Stella 现有权限、账户和接收范围边界。Agent 不得自行扩大接收对象或提升发送权限。

## 3. 移除现有备用渠道

- Stella 现有定时任务和待办提醒都提供“备用渠道”配置，投递失败后还可能改投备用目标。本轮移除这项功能：一次主动发送只选择一个渠道和一个接收目标；该渠道失败就报告失败，不再自动尝试第二渠道或第二接收人。
- 定时任务和待办提醒的创建、编辑、详情及测试发送界面均不再显示或提交备用渠道开关、备用接收人及相关字段。Agent 工具和外部接口也不能新建或修改备用配置；新请求携带备用配置时应明确拒绝，而不是保存后静默忽略。
- 已保存的任务和提醒可能含有 `backup_enabled`、`backup` 等旧字段。读取旧数据时只保留原首选目标，不执行、展示或恢复旧备用目标；再次保存时清除备用配置。若旧首选目标不属于本轮允许的三个主动发送渠道，标记为需要用户重新选择，不得自动切换到旧备用目标。旧 `web` 对话投递也不等同于新的客户端系统通知，不能未经用户确认就改变投递方式。
- 移除备用功能不得删除已有任务、待办或其历史执行记录；旧配置转换和投递失败的原因应可见。

## 4. 主动发送与备用渠道验收

1. 主动发送渠道选择器仅从“客户端 / Telegram Bot / 企业微信智能机器人”中列出**当前已连接**的渠道，可见选项数量为 0–3；未连接的渠道和其他现有渠道都不出现在列表中。一个渠道都未连接时，在列表外提示先连接。已保存的有效选择重新打开后保持一致。
2. 对三个渠道分别验证：未连接时选项不可见且不能发送；已连接但目标尚未建立可发送关系时，不允许发送并提示先建立目标关系；连接和目标均就绪后，即使**没有近期入站消息**，Stella 仍可向已授权目标主动发出一条消息，并能在目标侧确认收到。保存后断开连接时原设置保留、发送失败且原因可见，不自动改选。
3. 选择客户端后，用户已登录且允许通知的 Stella 电脑客户端出现由操作系统显示的通知，包含图标、标题和简短正文；Stella 处于后台、用户没有打开对话时也能提醒。仅在 App 内弹窗、新建对话或添加一条聊天消息均不满足此项验收；本轮不验收手机通知。Telegram 不要求用户再次发送消息，企业微信智能机器人不要求新的消息回调帧。
4. 未配置渠道、无效目标、撤销凭证、断线及平台拒绝等场景均给出明确失败结果，不记为发送成功，也不自动切换渠道。
5. 发送至未经授权的目标被拒绝；定时任务等无人值守触发也遵守同一权限边界。
6. 定时任务和待办提醒均没有备用渠道设置；界面、Agent 工具和接口不能创建新备用配置。选定渠道发送失败后只报告失败，第二渠道或第二接收人未收到消息。
7. 读取含旧备用字段的任务或提醒不报错、不删除原记录；旧备用目标不再展示或使用，保存后不再保留备用字段。旧首选渠道若已不受支持，显示需要重新选择渠道。

## 5. 设置入口整理

- 侧边栏现有“配置”入口改名为“设置”，仍进入统一设置页。现有基础配置、模型、Apple 集成等设置保留。
- 将简报页面内的设置面板迁入统一设置页的“简报”区域，完整保留邮箱、eLearning、动作授权和筛选规则的查看、修改、测试与错误反馈。简报页面原设置位置保留一个明确的按钮，点击后直接打开设置页的简报区域；简报页面不再并列维护第二份设置表单。
- 侧边栏底部只显示版本号和收起／展开侧边栏按钮，不再显示“更多”菜单、主题或语言快捷操作、检查更新入口、外部链接入口及更新横幅。主题与语言设置放入统一设置页；检查更新、文档、项目网站和反馈入口放入设置页的“关于／帮助”区域；日志继续使用侧边栏现有入口。功能仍可访问，但不再占用侧边栏底部。
- 从简报等业务页面的按钮进入设置时，设置页显示“返回原页面”按钮，并记住进入时的页面位置；切换设置页内部区域后仍可返回。直接从侧边栏进入设置时不显示该按钮。日程和待办页面现有的 Apple 集成设置跳转也应得到相同返回行为，且不改动这两个业务页面的设置范围。
- 本轮不把通道、安全、能力、日程分类、单个定时任务或待办的编辑选项迁入设置，也不改变它们现有的业务行为。能力页面的更名与工具展示要求见第 6 节。

### 设置整理验收

1. 侧边栏入口显示“设置”而非“配置”；原有基础配置、模型与 Apple 集成仍可正常访问。简报页按钮直达简报设置；原简报页不再展示设置表单，迁入后的全部配置功能与数据保持一致。
2. 侧边栏底部在展开和收起状态下均仅有版本号与收起／展开按钮；原底部菜单不再出现。主题、语言、检查更新及原外部链接在设置页可用，日志仍可从侧边栏进入。
3. 从简报、日程或待办进入设置时可见返回按钮；切换设置区域后点击仍返回原业务页面及进入前的位置。直接从侧边栏或应用菜单进入设置时没有返回按钮。
4. 通道、安全、能力、日程分类以及各业务对象的编辑入口保持原位，不因本轮设置整理丢失功能。

## 6. “进化”页面更新为“能力”

- 侧边栏现有“进化”入口改名为“能力”，进入后的页面标题也改为“能力”；英文界面同步使用对应的“Capabilities”名称。保留现有工具和技能两块内容及技能启停功能，不把该页面并入“设置”。保留当前 `/skills` 页面地址，从该地址和侧边栏入口进入时均显示“能力”页面。
- “内置工具”区域应展示 Stella 当前版本提供的**完整内置工具目录**，不能仅把 `ToolManager.tool_classes` 当成完整清单。尤其要纳入运行时单独注入的 `memory_search` 与 `memory_get`。工具缺少依赖、尚未配置、被关闭或仅在特定上下文可用时，仍应能在目录中看到，并准确标示不可用原因或适用条件；列表展示不意味着绕过现有权限或把工具注入所有 Agent。
- 每个内置工具都要有**中文和英文的展示标题、介绍及详情文案**。工具调用标识（如 `memory_search`）保持稳定、不翻译；界面根据当前中文／英文语言设置显示对应文案，不得让中文界面混入英文工具介绍或让英文界面混入中文工具介绍。面向 Agent 的工具调用说明不直接作为用户界面文案。
- 能力页的工具和技能条目默认折叠，折叠时只显示标题和展开提示；展开后显示**完整介绍**、当前可用状态与“查看详情”入口。不得使用两行省略号或其他方式截断正文；长内容可自然换行，页面可滚动。详情页完整显示对应条目的介绍与适用说明，并可返回原列表；技能原有启停能力保留。
- 内置工具与外部 MCP 工具须有清晰边界；MCP 工具不能被算入“内置工具”数量。技能区域继续展示技能，不与工具数量混算。获取工具或技能数据失败时显示可见错误和重试入口，不能将请求失败显示成“暂无内置工具”。

开发 Agent 请先读 [能力页面实施参考](capabilities.md)，其中列有项目代码入口、24 个内置工具的核对清单、中英文首版文案、接口和交互约束。

### 能力页面验收

1. 中文侧边栏与页面标题均显示“能力”，英文均显示“Capabilities”；打开原 `/skills` 地址和从侧边栏进入时显示同一页面。原工具、技能列表和技能启停操作仍可用。
2. 用当前版本的内置工具定义及 Agent 实际注入路径核对页面目录；`memory_search`、`memory_get` 必须列出，其他内置工具不得遗漏或重复。MCP 工具不混入内置工具计数。
3. 未配置、不可用或受上下文限制的内置工具仍有可辨认的状态说明；页面不会因列出工具而赋予 Agent 新权限。接口失败时展示错误和重试，不伪装成空列表。
4. 逐项核对全部内置工具：中文和英文界面分别显示完整、准确的本地化标题、介绍及详情，切换语言后当前页面同步更新；工具标识保持不变。两种界面都不以另一种语言的原始 Agent 描述代替缺失译文。
5. 工具和技能条目初始只显示标题与展开提示；键盘或鼠标展开后可读完全文并打开对应详情页，返回后仍能找到原条目。长文本在窄窗口也不出现无法继续阅读的省略号；技能启停仍可操作，展开行为本身不触发启停。

## 7. 桌面端页面顶部与内容布局统一

- 适用于桌面客户端侧边栏中的 Stella 内置页面及其列表／详情状态：聊天、事务、日程、简报、账单、健康、定时任务、记忆、知识库、渠道、能力、安全、设置、日志。登录、引导、弹窗和外部产品自行提供的页面不属于这轮页面统一范围。
- **只统一页面顶部标题区域的跨度**：有独立页面标题的页面，标题、说明和主要操作位于横向铺满主内容区的头部容器；页面级分隔线从主内容区左边缘连续延伸到右边缘。标题不能因下方内容居中而被包进同一窄列，标签线或卡片边框也不能代替页面级分隔线。应用窗口现有标题栏分隔线保持一致，不叠加重复线。聊天页当前没有独立页面标题，不为统一样式强行增加一行标题。
- **标题下的具体内容按功能设计**：卡片列表、表单、文章阅读区、日历、图表、聊天记录和详情可以选择居中限宽、网格、分栏或铺满。例如用户截图中的定时任务卡片可以保持合适的内容宽度；不要求这些卡片强行撑到窗口两边。已有 `max-w-* mx-auto` 不能一概删除，仅当内容本身需要调整时再修改。
- 头部及内容在宽、窄窗口和侧边栏展开／收起状态下都应正常响应，不出现横向溢出、控件遮挡或不可读内容。页面内部的标签线、表格线和卡片边框仍表达局部结构。具体代码位置、页面核查清单和开发验收见 [界面统一实施参考](ui-consistency.md)。

### 界面统一验收

1. 逐一打开有独立标题的内置页面及其详情状态：标题区域与页面级分隔线完整横跨主内容区；居中正文不能缩短标题或横线，也没有相邻重复线。聊天页保留现有无独立标题结构。
2. 对照用户给出的定时任务卡片示例：标题区域全宽，而其下方卡片仍可按阅读与操作需要保持居中或限宽；其他页面的列表、表格、分栏、日历、聊天和详情也按各自内容设计，不因本轮统一被强制拉满。
3. 宽／窄窗口及侧边栏展开／收起时没有水平滚动、遮挡或不可读内容；原有业务操作、页面切换、详情返回、内部标签和滚动位置仍可使用。实际界面验证要覆盖标题线和主体布局，不只检查样式类名。

开发时用隔离的测试账户、目标和数据验证，不能向真实用户或群组发送测试消息。改变可观察行为时先写失败测试，再实现；按仓库规则运行适用检查，并分别报告 PASS、FAIL、SKIP。本文记录需求，不表示代码实现、发布或合并已完成。
