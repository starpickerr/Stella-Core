# 安全中心凭据与权限整理：需求与验收

状态：2026-10-11 已确认需求，尚未实施。当前只维护 `.agents/task` 文档，暂不修改功能代码。本文包含凭据清单、权限分层和分支命名三部分，是本轮唯一的需求范围；[代码现状与实施线索](current.md)只供定位，不代替验收。

## 目标与边界

安全中心当前“凭据”页把已保存清单、再次填写密钥的表单、应用访问密码放在一起。模型密钥本来就在“设置 → 模型”中维护，访问密码也已在“设置 → 通用”中维护。用户无需在安全中心再面对另一套录入入口或一份与模型厂商目录不一致的固定下拉名单。

本轮将安全中心的凭据功能收敛为**已保存凭据的可见清单与逐项删除**。清单是实际保存状态，不是 Stella 支持的厂商目录；没有保存的厂商不出现。安全中心不得显示密钥明文，也不声称这里提供额外加密层。模型密钥仍在“设置 → 模型”新增、修改；浏览器访问 Stella 所用的应用访问密码仍在“设置 → 通用”管理。现有终端、文件工具对密钥的保护继续由其原有权限边界承担。

## 1. 安全中心信息结构

- 移除独立的“凭据”标签页；把精简的“已保存凭据”清单放到安全中心“总览”中，保留现有已配置凭据数量，并使数量与清单一致。列表有明确标题、无数据提示、加载与失败反馈。
- 清单每项显示易懂名称、凭据标识和实际保存来源（模型配置、`~/.stella/.env`，或两处都有），只显示“已配置”状态，绝不回显、复制、导出或记录密钥值。来源文案要准确；不要把普通 `.env` 文件称作独立加密凭据库。
- 每项提供“删除”操作；删除前说明影响并要求确认，防止误删。删除成功后即时刷新清单、数量以及模型设置中的配置状态；失败时显示原因、保留原状态。键盘与鼠标均可操作。
- 清单旁提供“前往模型设置”入口，指向“设置 → 模型”。该入口用于新增或修改模型厂商密钥，不是打开安全中心的另一份表单。从安全中心跳转后，使用设置页现有的返回来源机制返回安全中心。
- 删除安全中心的服务选择器、密钥输入框、“其他凭据”自定义名称输入和保存按钮，以及依赖这些表单的固定厂商名单和文案。安全中心不提供新增或修改密钥的第二套入口。其他非模型凭据本轮只需在清单中展示和删除，不为其新造编辑器。
- 删除安全中心内的“应用访问密码”卡片及修改框；“设置 → 通用”中已有的密码配置与登录行为继续可用。不要把应用访问密码列为服务凭据，也不要把其状态计入凭据数量。

## 2. 清单的真实范围与一致性

- 清单从实际保存的数据生成，不从厂商选项表推断。列出有非空值的模型配置密钥（包括内置厂商和用户保存的自定义模型厂商密钥）以及 `.env` 中名称以 `_API_KEY` 或 `_TOKEN` 结尾、值非空的凭据；匹配时按实际环境变量大写命名规则处理。没有值的 OpenAI、Claude 等不显示。
- 同一个凭据在模型配置和 `.env` 都有值时只显示一项，并准确标明两处来源。自定义模型厂商即使不在固定厂商名单中，只要已存密钥也应可识别；名称足以区分多个自定义厂商。
- 模型设置中新增、修改或删除密钥后，刷新安全中心应显示对应状态。安全中心删除后，刷新模型设置应显示密钥已清除；不能有一处显示“已删除”而另一处仍把它当作有效密钥。
- 删除是对**所选凭据**的实际撤销：仅清除该凭据在持久化配置、`.env` 及必要的运行时同步副本中的有效值，不删除厂商条目、模型选择、API 地址或无关凭据。若同名值来自两处，确认后应清除两处，避免刷新或重启后“重新出现”。正在使用的模型可能因此无法请求；确认文案要明确这一点。
- 清单、接口响应、错误信息和安全日志均不得包含密钥明文。现有权限规则、终端和文件读取限制不因移除表单而放宽。

## 3. 验收场景

1. 只保存 `deepseek_api_key` 时，总览清单只显示 DeepSeek 一项及正确来源，数量为 1；未保存的 OpenAI、Claude 不出现。安全中心没有“凭据”标签页、厂商下拉框或密钥输入框。
2. 在模型设置中保存 MiniMax、智谱、豆包和至少一个自定义厂商密钥后，刷新安全中心均能看到这些已保存项；未保存的其他厂商不出现。通过“前往模型设置”可到达模型页并返回安全中心。
3. `.env` 中存在有值的 `GITHUB_TOKEN`、空值的 `EMPTY_API_KEY` 和不属于凭据的普通大写变量时，清单仅新增 GitHub 凭据；不得把普通变量当密钥。清单不含任何明文。
4. 同一凭据同时存在于模型配置和 `.env` 时只显示一项，标明两个来源；确认删除后两处有效值均消失，刷新及重启后不复现，其他密钥与厂商设置不受影响。
5. 删除内置或自定义模型密钥后，模型设置显示未配置；取消删除或删除失败时，原凭据仍保持有效且界面准确。删除操作具备可理解的确认、成功与失败反馈。
6. 应用访问密码只在“设置 → 通用”维护，原有浏览器登录保护与修改功能可用；安全中心清单不含访问密码，数量不计入它。
7. 中文、英文界面的清单名称、来源、确认和错误文案都可读；键盘可完成跳转与删除。原有安全总览、权限、项目与对话、外部连接、安全活动功能保持可用；文件与终端仍不能通过该改动读取密钥。

## 4. 三层权限方案的生效规则

权限仍按**默认权限 → 项目 → 对话**依次确定。每层可以有自己的方案，也可以不保存方案而继承前一层已经选中的方案。后一层一旦保存自己的方案，就以该层的完整预设或自定义规则为准，不能把前一层残留的规则差异混进来；没有自己的方案时，显示和执行都使用前一层的实际方案。预设包括“只读”“工作区写入”“完全访问”，第四个选项是“自定义”。默认权限页只修改全局方案，不隐式改写任何项目或对话保存的方案；既有安全硬边界、确认流程和其他非方案配置仍然有效。

方案名必须来自同一个实际生效的方案，而不是因为某层没有单独配置就把标题写成“继承”或“自定义”。来源可以用辅助文案标识“来自默认权限／项目／本对话”，但不能代替具体方案名。当前代码的规则目录是 **11 项**；本轮沿用这 11 项，不新增第 12 项。预设页面只展示方案名称和对应说明，不把规则表展开为重复的 11 项清单。

选择“自定义”先进入**未保存的编辑草稿**，以当前实际生效规则为起点供调整；只有点击“保存自定义”才把方案与规则写入所选层。取消编辑或切换离开时，不得留下自定义方案或复制规则的持久化记录。编辑现有自定义时读取该层自己保存的规则，保存后只作用于该层。旧数据中仅保存部分规则差异的项目或对话必须保持原来的有效限制；转换到新展示/保存语义时不得意外放宽权限。

## 5. 安全页“项目与对话”

**项目：**先明确选一个项目，只展示这个项目的权限方案区。标题始终是具体方案名，正文是对应方案说明。

- 项目没有自己保存方案：显示默认权限当前实际选中的方案。默认是完全访问就显示“完全访问”及其说明，默认是只读就显示“只读”及其说明；默认是自定义也显示“自定义”，但规则属于默认层，项目区域不展开规则表。
- 项目自己保存预设：只显示该预设的名称和说明，不显示规则表。
- 项目自己保存自定义：显示基础方案和本项目可修改的完整 11 项规则；“保存自定义”仅写入当前所选项目。选择自定义但尚未保存时可编辑草稿，取消不写入。项目选择切换后，不得把前一个项目的草稿或保存操作作用到另一个项目。

**对话：**先明确选一条对话，而不是始终跟随当前打开的对话；在区域标题或紧邻标题的位置标明该对话属于哪个项目，没有项目时明确显示默认工作区。以下操作都只作用于所选对话。

- 对话没有自己保存方案：显示其所属项目的实际方案；项目也没有保存方案时显示默认方案。继承到“自定义”时仍显示“自定义”，但不在对话区域开放规则编辑。
- 对话自己保存预设：只显示预设名称和说明，不显示规则表。
- 对话自己保存自定义：显示基础方案和这条对话可修改的完整 11 项规则；保存后只作用于这条对话。选择自定义但尚未保存时可编辑草稿，取消不写入。切换对话不得带入其他对话的草稿或状态。
- 选中的项目与选中的对话是两个独立上下文；查看某条对话时，用该对话**实际所属项目**计算方案，不以项目下拉框当前选择代替其归属。更改项目方案后，继承它的对话随之更新；自有方案的对话保持原方案。

每个作用层级只呈现一组“只读／工作区写入／完全访问／自定义”选择，说明区不再复制一组控制项。项目和对话的预设区域不重复展示规则清单。额外允许访问的目录是单独的授权设置，保留为独立区域或入口；不放进方案名称、说明、输入框权限芯片提示或这 11 项规则表里。调整目录不得顺带把继承中的对话保存成自定义方案；恢复继承也不得误删独立的目录授权。

## 6. 安全页与对话输入框的统一入口

- 安全页和输入框必须读写同一份全局、项目和对话权限数据，并通过同一套方案定义显示名称与说明。输入框只显示当前对话的实际方案名并提供四种方案选择，不提供 11 项规则编辑器；需要编辑自定义时进入安全页对应对话的编辑草稿，保存后再更新芯片。
- 在安全页选择某条对话并保存预设或自定义后，这条对话的输入框显示同一方案名；输入框选择并保存预设后，安全页再选中这条对话时只显示其名称和说明。两个入口相互刷新时，不能继续显示过期状态。
- 输入框“设为项目默认”将当前对话**实际生效**的方案写到该对话所属项目；预设写为预设，自定义写为包含当前有效规则的项目自定义。项目区域随后按“自己保存”的类型展示：预设只有名称/说明，自定义才有可编辑规则。没有所属项目时该操作不可用，并说明原因。
- 输入框“恢复继承”只清除这条对话自己保存的方案；芯片与安全页立即显示项目方案，项目没有自己的方案时显示默认权限方案。它不能清除项目方案、默认方案或与方案独立的目录授权。
- 输入框不再提供把当前对话方案直接写为**全局默认**的快捷操作；全局方案只在“默认权限”页修改。安全页中项目、对话及输入框的保存动作不得误写其他层级。

## 7. 权限验收场景

1. 默认权限分别设为只读、完全访问、自定义；未保存方案的项目和对话均显示具体生效方案名与说明，不出现可编辑规则表。默认自定义的规则只在默认权限页可编辑。
2. 项目保存工作区写入时，项目区域只显示名称/说明；其未设方案的对话及输入框显示工作区写入。对话再保存只读后，项目仍是工作区写入，该对话及输入框都显示只读；其他对话不受影响。
3. 项目或对话选“自定义”后取消，存储状态与原有有效权限均不变；保存后仅该层出现基础方案及完整现有 11 项可编辑规则。切换项目或对话时没有草稿串用。
4. 默认层是带规则差异的自定义，项目选择同一基础预设或另一预设后，该项目按新预设完整生效，不夹带默认层的差异；对话选择预设时同理。旧的部分规则差异记录仍维持原来的安全效果，不因新合并方式放宽。
5. 安全页可选择非当前打开的对话，正确显示其所属项目、方案名和来源；保存只改所选对话。输入框切到该对话后显示同一名称。对话不属于项目时使用默认层。
6. 输入框选择预设后，安全页对应对话只有名称/说明；输入框选择自定义会进入该对话在安全页的草稿，未保存前芯片与存储仍显示旧方案，保存后两处同步。输入框不出现规则表或“设为全局默认”。
7. “设为项目默认”复制当前对话的实际预设或自定义规则到所属项目；“恢复继承”只去掉对话自己的方案，随后两处显示项目或默认层的具体方案名。其他项目、对话及额外目录授权不受影响。
8. 目录授权位于独立区域，增删目录不改变方案所有权或显示名称；恢复继承不清除目录。中英文方案名称与说明一致可读，错误、空列表和保存失败均有可见反馈。

## 8. 分支命名要求

后续为这些需求建立开发分支时，以**实际工作内容**命名，例如 `feature/security-policy-inheritance`、`fix/security-credential-list`；仅修改文档的分支可用 `docs/security-center-requirements`。分支名不得以 `codex/`、`cursor/`、`ai/` 或其他 AI 工具、模型名称作为功能前缀。不要为了满足命名要求改写或删除已有共享分支的历史；从当前开发基线建立或在本任务专用分支上按 Git 规则工作。

后续获得功能实施指令后，先写能失败的行为测试，使用隔离数据核对凭据列表、跨入口状态、三层覆盖与删除语义；运行仓库适用检查，并在桌面实际界面验证总览、方案选择、跳转和保存。检查结果分别报告 PASS、FAIL、SKIP。不要用真实用户密钥或真实项目数据做测试。
