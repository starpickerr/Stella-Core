# 安全中心凭据与权限整理：需求与验收

状态：2026-10-11 已确认需求，尚未实施。本文包含凭据清单与权限分层两部分，是本轮唯一的产品范围；[代码现状与实施线索](current.md)只供定位，不代替验收。

## 目标与边界

安全中心当前“凭据”页把已保存清单、再次填写密钥的表单、应用访问密码放在一起。模型密钥本来就在“设置 → 模型”中维护，访问密码也已在“设置 → 通用”中维护。用户无需在安全中心再面对另一套录入入口或一份与模型厂商目录不一致的固定下拉名单。

本轮将安全中心的凭据功能收敛为**已保存凭据的可见清单与逐项删除**。清单是实际保存状态，不是 Stella 支持的厂商目录；没有保存的厂商不出现。安全中心不得显示密钥明文，也不声称这里提供额外加密层。模型密钥仍在“设置 → 模型”新增、修改；浏览器访问 Stella 所用的应用访问密码仍在“设置 → 通用”管理。现有终端、文件工具对密钥的保护继续由其原有权限边界承担。

## 1. 安全中心信息结构

- 移除独立的“凭据”标签页；把精简的“已保存凭据”清单放到安全中心“总览”中，保留现有已配置凭据数量，并使数量与清单一致。列表有明确标题、无数据提示、加载与失败反馈。
- 清单每项显示易懂名称、凭据标识和实际保存来源（模型配置、`~/.stella/.env`，或两处都有），只显示“已配置”状态，绝不回显、复制、导出或记录密钥值。来源文案要准确；不要把普通 `.env` 文件称作独立加密凭据库。
- 每项提供“删除”操作；删除前说明影响并要求确认，防止误删。删除成功后即时刷新清单、数量以及模型设置中的配置状态；失败时显示原因、保留原状态。键盘与鼠标均可操作。
- 清单旁提供“前往模型设置”入口，指向“设置 → 模型”。该入口用于新增或修改模型厂商密钥，不是打开安全中心的另一份表单。从安全中心跳转后，使用设置页现有的返回来源机制返回安全中心。
- 删除安全中心的服务选择器、密钥输入框、“其他凭据”自定义名称输入和保存按钮，以及依赖这些表单的固定厂商名单和文案。安全中心不提供新增或修改密钥的第二套入口。其他非模型凭据本轮只需在清单中展示和删除，不为其新造编辑器。
- 删除安全中心内的“应用访问密码”卡片及修改框；“设置 → 通用”中已有的密码配置与登录行为继续可用。不要把应用访问密码列为服务凭据，也不要把其状态计入凭据数量。

## 2. 清单的真实范围与一致性

- 清单从实际保存的数据生成，不从厂商选项表推断。列出有非空值的模型配置密钥（包括内置厂商和用户保存的自定义模型厂商密钥）以及 `.env` 中名称以 `_API_KEY` 或 `_TOKEN` 结尾、值非空的凭据；匹配时按实际环境变量大写命名规则处理。没有值的 OpenAI、Claude 等不显示。
- 同一个凭据在模型配置和 `.env` 都有值时只显示一项，并准确标明两处来源。自定义模型厂商即使不在固定厂商名单中，只要已存密钥也应可识别；名称足以区分多个自定义厂商。
- 模型设置中新增、修改或删除密钥后，刷新安全中心应显示对应状态。安全中心删除后，刷新模型设置应显示密钥已清除；不能有一处显示“已删除”而另一处仍把它当作有效密钥。
- 删除是对**所选凭据**的实际撤销：仅清除该凭据在持久化配置、`.env` 及必要的运行时同步副本中的有效值，不删除厂商条目、模型选择、API 地址或无关凭据。若同名值来自两处，确认后应清除两处，避免刷新或重启后“重新出现”。正在使用的模型可能因此无法请求；确认文案要明确这一点。
- 清单、接口响应、错误信息和安全日志均不得包含密钥明文。现有权限规则、终端和文件读取限制不因移除表单而放宽。

## 3. 验收场景

1. 只保存 `deepseek_api_key` 时，总览清单只显示 DeepSeek 一项及正确来源，数量为 1；未保存的 OpenAI、Claude 不出现。安全中心没有“凭据”标签页、厂商下拉框或密钥输入框。
2. 在模型设置中保存 MiniMax、智谱、豆包和至少一个自定义厂商密钥后，刷新安全中心均能看到这些已保存项；未保存的其他厂商不出现。通过“前往模型设置”可到达模型页并返回安全中心。
3. `.env` 中存在有值的 `GITHUB_TOKEN`、空值的 `EMPTY_API_KEY` 和不属于凭据的普通大写变量时，清单仅新增 GitHub 凭据；不得把普通变量当密钥。清单不含任何明文。
4. 同一凭据同时存在于模型配置和 `.env` 时只显示一项，标明两个来源；确认删除后两处有效值均消失，刷新及重启后不复现，其他密钥与厂商设置不受影响。
5. 删除内置或自定义模型密钥后，模型设置显示未配置；取消删除或删除失败时，原凭据仍保持有效且界面准确。删除操作具备可理解的确认、成功与失败反馈。
6. 应用访问密码只在“设置 → 通用”维护，原有浏览器登录保护与修改功能可用；安全中心清单不含访问密码，数量不计入它。
7. 中文、英文界面的清单名称、来源、确认和错误文案都可读；键盘可完成跳转与删除。原有安全总览、权限、项目与对话、外部连接、安全活动功能保持可用；文件与终端仍不能通过该改动读取密钥。

## 4. 三层权限方案与显示

权限继续按**默认权限 → 项目 → 对话**依次确定。后一层自己保存了方案，就以该层的完整预设或自定义规则覆盖上一层的方案；没有保存方案，就使用上一层已经选中的实际方案。预设为“只读”“工作区写入”“完全访问”，第四个选项是“自定义”。预设只展示具体名称及其说明，不重复展示规则表。方案标题不能仅写“继承”，也不能把实际生效的预设误写成“自定义”；需要标注来源时，另用辅助文案显示“默认权限／项目／本对话”。

当前规则目录是 **11 项**，本轮沿用现有 11 项，不增添新规则。只有某层**自己保存了自定义**，该层在稳定状态下才显示基础方案和可编辑的完整规则表。选“自定义”可以先打开本层的未保存草稿，以当前实际生效规则为起点；点“保存自定义”才写入，取消、切换层级或离开页面都不保存草稿。旧数据中仅保存部分规则差异的项目或对话必须保持原有效果；调整覆盖逻辑时不得意外放宽权限。现有安全硬边界与其他非方案配置继续生效。

## 5. 安全页“项目与对话”

**项目。** 先选一个项目，下面只展示这个项目的方案区，标题始终为具体方案名，正文为对应说明。

- 未保存项目方案：显示默认权限当前实际选中的方案。例如默认为完全访问就显示“完全访问”及其说明，默认为只读就显示“只读”及其说明；默认为自定义时也显示“自定义”，但规则属于默认层，不在项目区开放规则表。
- 自己保存预设：只显示该预设的名称和说明，不展示 11 项规则。
- 自己保存自定义：显示基础方案和本项目可修改的 11 项规则；保存后只写入所选项目。切换项目不能把前一个项目的草稿或保存结果带到新项目。

**对话。** 先选一条对话，不再只跟随当前打开的对话；标题旁明确显示该对话所属项目，没有项目时显示默认工作区。对话方案始终用它**实际所属项目**计算，不用项目下拉框当前选择代替其归属。

- 未保存对话方案：显示所属项目的实际方案；项目没有方案则显示默认权限的方案。继承到自定义时标题仍是“自定义”，但这份规则属于上层，对话区不开放编辑。
- 自己保存预设：只显示预设名称和说明，不展示规则表。
- 自己保存自定义：显示基础方案和仅作用于这条对话的 11 项可编辑规则；保存后只写入所选对话。切换对话不能串用草稿、来源或保存目标。
- 项目方案改变时，继承该项目的对话随之更新；自己保存了方案的对话保持原方案。选中的项目和对话是两个独立上下文。

“默认权限”页只修改全局方案，不隐式改写项目或对话；该页选择自定义时也要先编辑、后保存。各作用层级各有一组“只读／工作区写入／完全访问／自定义”选择，说明区不再复制方案控制项。额外允许访问的目录是独立授权设置，保留在单独区域或入口，不放进方案名称、说明、规则表或输入框权限芯片提示；增删目录不能顺带让继承中的对话变成自定义方案。

## 6. 对话输入框与安全页共用权限

- 两处读写同一份默认、项目、对话权限数据，并用同一套方案定义显示名称和说明。输入框只显示当前对话的实际方案名、提供四种方案选择，不在输入框展示或编辑 11 项规则。
- 安全页选中一条对话并保存方案后，该对话的输入框显示相同名称；输入框保存预设后，安全页再选中该对话时显示同一预设的名称和说明。跨入口刷新不能留有过期状态。
- 输入框选择“自定义”时，打开安全页**该对话**的未保存编辑草稿；保存前不改输入框芯片或持久化状态，保存后两处同步。输入框不直接提交一份规则副本。
- “设为项目默认”把当前对话**实际生效**的方案写到它所属的项目。预设写为预设；自定义写为包含当前有效规则的项目自定义，项目区随后才显示可编辑规则。没有所属项目时不可操作，并说明原因。
- “恢复继承”只清除该对话自己保存的方案。芯片和安全页立即改显示项目方案，项目没有方案则显示默认权限方案；项目和默认层不被改写。
- 输入框不再提供“设为全局默认”快捷操作；全局方案只能到安全页“默认权限”修改。各入口保存时必须明确目标层级及所选对话，不能误写当前打开的其他对话。

## 7. 权限验收场景

1. 默认权限分别设为只读、完全访问、自定义；未保存方案的项目和对话都显示对应具体名称与说明，不打开规则表。默认自定义的规则只在默认权限页可编辑。
2. 项目保存工作区写入后，项目只显示名称/说明；其继承中的对话与输入框显示工作区写入。某对话再保存只读后，只有该对话显示只读，项目和其他对话不变。
3. 在默认、项目或对话选“自定义”后取消，存储和有效权限不变；保存后仅该层显示基础方案及完整现有 11 项规则。切换项目或对话时草稿不串用。
4. 默认层为带规则差异的自定义，项目或对话另选预设后，新层按预设完整生效，不夹带上层的差异。旧的部分规则差异记录保留原来的安全效果，不因新逻辑放宽。
5. 安全页选非当前打开的对话，能正确显示其所属项目、方案名和来源；保存只改所选对话。打开这条对话后输入框显示同一方案；无所属项目时使用默认层。
6. 输入框改预设后，安全页只显示名称/说明；输入框选择自定义会进入对应对话的安全页草稿，未保存前两处仍显示旧方案。输入框没有规则表或“设为全局默认”。
7. “设为项目默认”复制当前有效预设或自定义规则到所属项目；“恢复继承”只清除对话方案，两处显示上层实际方案。额外目录授权保留，改变目录不改变方案归属。
8. 中文和英文的方案名称、说明、来源与错误反馈可读；保存失败、对话列表为空、所选项目或对话失效时，界面不误报成功，也不写到其他对象。

实施时先写能失败的行为测试，使用隔离数据核对凭据列表、跨入口一致性、三层覆盖、旧配置安全性与删除语义；运行仓库适用检查，并在桌面实际界面验证总览、方案选择、跳转和保存。检查结果分别报告 PASS、FAIL、SKIP。不要用真实用户密钥或项目数据做测试。
