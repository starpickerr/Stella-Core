# Stella 当前迭代需求与验收

状态：2026-10-10 整理，可交给开发 Agent。本文只定义目标行为；技术推测和未采纳的建议留在 [讨论记录](current.md)。

## 1. 简报生成

### 目标行为

- 删除本次生成中抓取期间的预览工作线程、提前筛选和预览正文。等本次所选来源抓取完成后，按最终候选进入一轮正式筛选与正文流程；候选多时允许在这轮流程中分批。不得再因等待预览结束而推迟正式生成。
- 保留已保存简报中、当前抓取窗口外的判断复用。来源错误、取消、重试、游标和已保存简报的恢复语义不得退化。不得修改真实用户的 `briefing.db` 做测试。
- 每批第一次调用 `briefing_decisions_result` 前，Agent 的任务正文须包含本批全部精确 ID，以及完整的当前硬性校验规则：`decisions` 为列表；ID 来自本批、恰好覆盖一次；`selected` 为布尔；`reason` 为非空字符串；选中项的 `section` 为 `action` 或 `fyi`，`score` 为 0–100 的整数且布尔值无效，`summary` 为非空字符串。任务正文还须要求 `category`、`information_type` 等业务字段，并明确这些不是当前校验单独拒绝的条件。用户规则文稿决定筛选内容，不能覆盖提交格式。
- 工具 schema 尽可能在模型提交前表达同样的字段约束；运行时校验仍保持上述硬性条件。漏交、重复、未知 ID 或空摘要不能自动补默认值。初次提示与校验应共享规则定义或有防漂移测试。
- 提交被拒时，返回能直接修正的反馈：缺失、重复、未知 ID，以及按 ID 指明的错误字段、原因和合格格式。Agent 保留本批候选、规则和提交上下文，在同一次生成中修正后重交结果。格式修正不得重新抓取邮件或 eLearning；确需核对正文时，只读取本次已抓候选快照。全部通过校验后才继续正文和持久化；失败不得覆盖上一份已保存简报或推进来源游标。

### 验收

1. 多来源运行只进行最终筛选/正文流程，不调用预览 Agent；上一份已保存简报的窗口外判断仍能复用。
2. 首次模型请求含精确 ID 清单与所有硬性规则；缺项或空摘要被拒，Agent 得到具体修正指令，在同批候选上重交成功。
3. 模拟首次错误、再次正确的模型响应，断言每个来源只抓取一次；失败时旧正文、条目、窗口及游标不变。隔离运行，不连接真实账户或模型。

## 2. 知识库索引跳转

用户确认：增加 Stella 渲染功能前，`knowledge/index.md` 中 `[软件设计](assessment/software-design.md)` 能打开 `knowledge/assessment/software-design.md`；新增渲染后失效。代码对比显示新 `MarkdownLink` 先把 `.md` 链接路由到工作区预览，知识库内部链接回调未被调用。这是本次回归的直接触发点。

知识库视图中的相对 Markdown 链接优先由知识库导航处理；普通聊天中的工作区文件链接仍走工作区预览。按当前文档路径解析 `./`、`../` 和多层相对路径；`knowledge/` 前缀按知识库根路径解析。相同文件名不得回退到全库第一个同名文件；无法解析或越出知识库根目录时给出可见反馈，不打开错误页面。外部网址仍按外部链接行为处理，危险协议仍拦截。

验收：点击“软件设计”打开准确文件；嵌套 `README.md` 链接打开当前目录的目标；同名文件不串页；普通聊天工作区链接、外部链接和图片/数学/图表/PDF 渲染不回归。使用隔离浏览器交互验证。

## 3. 会话安全模式

- “完全访问”预设的 `high_risk` 改为 `allow`；对话栏和安全页选择“完全访问”立即生效，不再出现第二次“启用完全访问”确认。用户主动选择预设这一操作本身就是授权。
- 其他会话的私有工作区、托管数据、凭据和 Apple 系统授权仍由现有硬边界拦截；不能因预设变化而放开。
- 对话栏点击“自定义”只切换到自定义模式，不展开逐项规则编辑器；逐项规则只在侧边栏安全页编辑。保留已有自定义规则，不因切换模式而静默丢失；按现有策略继承规则处理。

验收：两个入口一击切换完全访问，权限判断为 `allow`；上述硬边界仍拒绝；对话栏没有逐项编辑器，安全页可以编辑并持久化自定义规则。用隔离策略和浏览器验证。

## 4. 定时任务运行权限

- 定时任务编辑窗增加“运行权限”选择按钮，提供“沿用绑定对话 / 只读 / 工作区写入 / 完全访问”。新建任务默认“沿用绑定对话”；已有任务未设置该字段时保持原有继承行为，不自动提权。列表和详情展示选择结果。此选择控制任务的执行权限，不改变通知渠道或绑定对话的工作区。
- 显式权限随任务保存，创建、编辑和“立即运行”均按同一任务权限执行。只有可信用户界面可以显式提高任务权限；Agent 创建或编辑任务不能自行设置更高权限。执行时继续应用私有工作区、托管数据、凭据、账户范围、连接和 Apple 系统授权的硬边界。若策略仍需交互审批，无人值守任务应尽快报告权限不足，不等待一小时。
- 定时简报等任务只有业务动作真正完成才记录成功。权限拒绝、超时、工具错误或未生成简报不得因 Agent 返回一段文字、或消息已发送而记为生成成功。失败状态和原因在任务页面可见。

验收：用户通过任务编辑窗设置权限后，保存/重新打开/立即运行/下一次调度均一致；旧任务无权限字段仍继承；伪造或 Agent 提交权限提升被拒；需要审批时不等待 3600 秒；简报工具失败时任务状态为失败，旧简报保留。测试与真实账户隔离。

## 全局交付条件

按计划分步先写失败测试再实现可观察行为；默认运行 `.venv/bin/python scripts/quality_check.py incremental`，UI 还须进行实际浏览器交互验证。分别记录 PASS、FAIL、SKIP。开发和提交遵循 `AGENTS.md` 及 `.agents/rules/git.md`；只有用户明确要求合并或更新 `develop` 时才改变它，也不推送远程或更新 `main`。本轮不扩展 eLearning 串行抓取优化，也不加入未确认的批次大小、部分暂存或专用重试协议。
