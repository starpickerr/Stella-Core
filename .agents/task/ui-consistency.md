# 桌面端界面统一实施参考：标题全宽、正文按需布局

本文配合 [需求与验收](requirements.md#7-桌面端页面顶部与内容布局统一) 使用。用户用定时任务卡片截图确认：**页面标题区域和页面级横线贯穿主内容区，标题下的卡片等具体内容按功能决定宽度**。截图仅说明布局关系，不把其中的任务、时间、开关或文案作为本轮需求。本文件基于 2026-10-10 的桌面端代码核查，供开发 Agent 定位和验收；界面尚未修改。

## 统一后的页面结构

以 `desktop/src/renderer/src/App.tsx` 中侧边栏右侧的主内容区域为边界，不把侧边栏或可选会话列表算进页面宽度。全局窗口标题栏已有一条贯穿主内容区的底线；有独立页面标题的内置页面在其下方使用统一的页面头部。头部从主内容区左缘延伸到右缘，容纳标题、简短说明和主要操作，底部是一条连续分隔线。正文可以另外选择合适宽度，不反过来限制头部。聊天页目前没有独立页面标题，保留其会话结构；标题栏与页面头部相邻时不叠加重复边框。

可复用的结构如下，类名仅示意，实际应沿用项目现有颜色与间距 token：

```tsx
<div className="flex-1 min-w-0 min-h-0 flex flex-col">
  <header className="shrink-0 border-b border-default px-4 sm:px-6 pt-5 pb-3">
    {/* 页面标题、说明、主要操作 */}
  </header>
  <main className="flex-1 min-w-0 min-h-0 overflow-y-auto px-4 sm:px-6 py-5">
    <div className="mx-auto w-full max-w-4xl">
      {/* 内容宽度示例：每页可按阅读、列表或分栏需求调整或取消限宽 */}
    </div>
  </main>
</div>
```

页面级分隔线放在全宽头部容器上，不放在 `max-w-*` 内容列、标签栏或卡片中；同一边界只画一条。标题和主要操作保持统一的左右内边距，正文宽度则由页面内容决定：定时任务、设置、阅读页可居中限宽；日历或双栏页面可铺满；卡片组可采用响应式网格。`max-w-* mx-auto` 可以继续用于正文，但不能包住页面级标题或横线。窄窗口应换行、折叠分栏或竖排，避免横向滚动和遮挡。

## 开发验收要点

1. 建议抽出或复用页面头部组件，统一标题、说明、操作和底线，避免每个页面独立写出不同高度和线宽；现有业务组件保持原职责。移动头部时保留原页面的滚动和操作逻辑，不要批量删除正文的 `max-w-*`。
2. 对表中的 14 类页面（含 `/models` 别名）逐个检查列表、详情、空状态、加载状态和标签切换；有独立标题的页面，其页面级线左右端应与主内容区两边界对齐。页面内标签线或卡片线可以是局部线，但不会与页面头部线重叠。
3. 在宽窗口、窄窗口及侧边栏展开／收起状态下实际运行桌面界面；检查头部横线连续、正文宽度适合内容、无水平溢出、交互控件不被遮挡，详情返回和滚动不退化。跨页面比较顶部标题基线、左右内边距、分隔线位置与颜色。
4. 改变可观察布局前按仓库规则增加适当的失败测试，完成后运行增量检查和浏览器交互验证；对视觉宽度与线条连贯性保留截图证据。
