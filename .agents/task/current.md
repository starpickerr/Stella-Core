### 方案判断与补充

1. 保留已确认的去预览方案：来源全读完后只做一次正式筛选和正文。它针对重复生成和等待预览线程结束；继续复用上次已保存简报中、当前窗口外的判断。
2. 正式筛选的提示词明确列出本批所有 ID 和字段要求，且说明严于运行时校验。工具 schema 至少表达能直接约束的字段，运行时仍用现有硬性条件拒绝漏项、重复项和空摘要；不把缺失内容自动补默认值。
3. 为每批提交记录结构化校验失败原因（如缺失 ID 数量、字段名；不记候选正文）。缺少或不合格的条目可只让模型补交这些 ID，再与已校验条目合并；仍须逐项严格校验，不能补默认值。对无效重试设可观察的上限/超时，超限后明确失败且保留已保存的简报。不能把“早点失败”误报成“生成成功”。具体上限和批次大小在实施时结合模型调用耗时验证。
4. 先核对 06:00 的安全决策与审批事件，确认一小时等待是否发生在工具调用前的权限门禁。定时任务需要在运行时做非交互权限检查：若当前策略要求审批，立即明确失败并提示需要调整授权，不留下无人处理的一小时等待，也不能绕过权限。给工具入口、服务获取、来源配置、流水线入口和退出增加阶段耗时与结果记录，以便排查其他阻塞点。调度器只有确认简报流水线完成并持久化后才报告生成成功，超时或中断要报告失败。
5. 验收同时覆盖：多来源候选只生成一次；提交缺项能迅速给出明确失败或修正；定时任务阻塞有阶段定位且不会假报成功。用隔离的测试数据验证，不接触真实 `briefing.db`。目前缺少新实现和新运行证据，不能宣称卡顿已解决。

### 本轮讨论的具体设计

- 预览：用户确认删除同一次生成里的 `_PreviewWorker`、提前筛选和预览正文；所有来源就绪后只进入一轮正式筛选与正文流程，候选较多时仍可在这轮流程内分批。上次已保存简报的窗口外判断继续复用。
- 校验：用户已确认首次任务必须明示完整的实际校验规则。每批首次调用前，任务正文列出该批全部 ID，并逐项说明：`decisions` 为列表；每个 ID 必须恰好出现一次，不得遗漏、重复或加入未知 ID；`selected` 必须是布尔值；`reason` 必须是非空字符串；`selected=true` 时，`section` 只能是 `action` 或 `fyi`，`score` 必须是 0–100 的整数（布尔值无效），`summary` 必须是非空字符串。另继续说明 `category`、`information_type` 等写作要求，并标明这些不是当前校验单独拒绝的条件。工具 schema 尽可能表达同一套约束，运行时校验兜底；提示词和校验应从同一规则定义生成或有对应测试，防止以后再失配。漏项不能自动补默认值。
- 退回与重交：拒绝结果要给 Agent 明确的缺失、重复和未知 ID，以及按 ID 指明无效字段、实际问题和合格格式；对 `decisions` 结构错误同样给出可操作提示。Agent 保留本批候选、用户规则及上次提交内容，在同一次生成中修正后只重新调用结果工具。格式修正不得重跑来源抓取；确需核对原文时，只从本次已抓取的候选快照读取，不能再次访问邮箱或 eLearning。必须整批校验通过后才进入正文与持久化；失败重试设上限且不丢失上一份已保存简报。验收覆盖首次规则可见、具体退回提示、同批修正成功、来源抓取次数不增加。逐条暂存与仅补交问题 ID、批次大小是待讨论的进一步优化。
- 定时任务权限按钮：在任务编辑窗提供“运行权限”，建议选项为“沿用绑定对话 / 只读 / 工作区写入 / 完全访问”，默认沿用绑定对话；已有任务按既有权限来源解释，不自动提权。显式选择随任务保存，列表与详情展示当前选择；修改任务权限需要可信用户操作，Agent 创建或编辑任务不能自行提高权限。执行时以任务选项和现有工作区、账户、系统授权边界核验；若仍需审批，立即返回可见失败，不等待一小时。当前编辑器只有执行对话和通知渠道，没有这项权限选择。任务级自定义规则是否需要另行讨论。
