# Git 提交与分支规则

## 历史依据

`main` 最近提交以已审查的功能、修复、重构和合并提交为主；`develop` 同时存在 `feat:`、`fix:`、`test:`、`docs:` 等前缀和简洁英文动词句。沿用该习惯，不强制所有提交使用同一种前缀或作用域。

## 分支职责

- `main` 是正式版本；日常开发不直接提交或自动合并到 `main`。
- `develop` 是开发基线。修改代码或配置前从当前 `develop` 建专用分支，在分支完成提交与验证。用户已授权功能完成后及时合并回本地 `develop`；合并前检查工作区、测试和冲突。未授权不得推送远程。
- `develop → main` 是发布操作，须完成适用的单元、集成、UI、静态、构建及审查后，再取得用户对该发布的明确授权。禁止强推、改写共享历史或未经授权删除远程分支。

## 提交

- 一个提交对应一组逻辑相关的改动；标题简洁、准确，可用历史中的 `feat:`、`fix:`、`docs:`、`test:`、`chore:` 等类型或清楚的英文动词句。
- 不使用单独的 `update`、`fix`、`changes` 等模糊标题；不混入无关文件。
- 不添加 `Co-authored-by`、`co-worker`、AI 署名或无关尾注。不要修改 Git 全局配置或已有提交历史。
- 已有未提交修改先保留并识别归属；不得以 reset、clean 等破坏性方式消除障碍。
